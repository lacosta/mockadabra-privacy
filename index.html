In short

Mockadabra is a local-first developer tool. Everything it stores stays in your own browser profile. The extension has no account, no server, no analytics, no advertising and no telemetry, and the extension itself sends no data to the publisher or to any third party.

It does, however, sit in the path of web requests that your web pages make on the sites you enable. It is important to understand what that does and does not mean:

  • Mockadabra does not stop websites or their backend services from receiving data. Requests that it passes through, and requests of rules that modify a real response, are sent to the real server by the page, exactly as the page made them (plus only the changes a rule you wrote asks for). The server receives whatever the page and your browser normally send.
  • When a rule mocks a request or simulates a network failure, that request is answered or failed locally and is not sent to the real server.

Three kinds of requests

1. Requests made by the web pages you use (intercepted or passed through)

On sites that you enabled and Chrome granted, Mockadabra wraps the page's fetch and XMLHttpRequest. For each request it reads the method, the URL, the headers the page's script set and, for requests with a text body, a short preview (up to 16 KB) in memory, to decide whether one of your rules matches. Then:

What happens to a request, and whether it reaches the real server
What happensReaches the real server?
No rule matchesYes — unchanged
A rule passes through while adding request headersYes — with the headers you configured added
A rule modifies the real responseYes — the real server answers; Mockadabra changes the response in the page according to your rule
A rule mocks the responseNo — answered locally
A rule simulates a network failureNo — failed locally
The engine cannot decide (for example a configuration error)Depends on your failure policy: non-mutating requests continue unchanged; by default mutating ones (POST, PUT, PATCH, DELETE) are blocked rather than sent

A mocked response is delivered to the page that made the request. Scripts of that page — including third-party scripts it loads — can read it like any other response. Mockadabra does not hide its own activity from the page.

2. Requests initiated by the extension itself

None. The extension's code contains no fetch, XMLHttpRequest, WebSocket, beacon or other network call of its own, and the production package contains no address of any publisher, analytics, update or advertising service. It loads no remote code and no remote fonts or images.

3. Data stored locally on your device

Described in the next section.

What is stored locally

All of this lives in your browser profile (the extension's IndexedDB and chrome.storage) and is removed when you uninstall the extension:

  1. Configuration you create — projects, groups, rules, response definitions (status, headers, bodies, delays), environments, variables, enabled-site lists and settings.
  2. Secret variables you create — stored unencrypted. They are masked in the dashboard, excluded from exports unless you opt in, and never written to the activity log. A rule can place a secret into a mocked response only if you explicitly allow it for that rule, and then the page that receives the response can read it.
  3. Activity log — for diagnostics Mockadabra keeps a bounded log (by default the 500 most recent entries; logging is on by default) of events such as “GET https://example.com/api/items → rule X (mock)” or “request not matched”. It records the HTTP method, the URL without its query string or fragment, the rule involved and the outcome. It does not record request or response bodies or header values. Version 0.1.0 has no screen to view, pause or clear it.
  4. Per-tab choices — which project/environment (or “off”) each tab uses, in chrome.storage.session, which Chrome clears when the browser restarts and when the tab closes.
  5. Safety copies — before an import, a copy of your own workspace is kept in the profile (the newest 10).
  6. The current tab's address — when you open the toolbar popup, the extension reads the URL of the tab you opened it on (Chrome's activeTab permission) to show whether Mockadabra is active there. It is not stored.

Request details described under “Three kinds of requests” (headers, body previews, real responses being modified) are processed in memory and are not stored, except for the log entries above.

Mockadabra does not read your cookies, passwords, browsing history or page content beyond what is described here, and it only runs on sites that are both enabled by you and granted by Chrome.

Where data goes

  • Nowhere outside your device, by the extension. It does not sell, share or transfer user data, and does not use it for advertising, creditworthiness, lending or any purpose unrelated to its single purpose (mocking and modifying API responses for development and testing).
  • The web requests that pages make to their own servers are the page's traffic, not the extension's; see the table above.
  • Mockadabra cannot protect data you choose to put into a mock: do not store production credentials in responses or variables.

Import and export

  • Export writes a plain-text JSON file to your computer (Downloads folder) only when you ask. Secret values are left out unless you tick the option to include them; if you do, the file is not encrypted and its name says so. Activity logs and per-tab choices are never exported.
  • Import reads only a file you choose, validates it completely, and writes nothing until you confirm. Importing never grants Chrome site access.
  • Where you keep exported files (cloud drives, repositories, e-mail) and who can read them is your responsibility.

Your choices and control

  • Delete part of your data: delete rules, groups, environments, variables or whole projects in the dashboard. Importing a workspace file in Replace mode replaces everything.
  • Stop it running on a site: switch mocking off for a tab in the popup, remove the site from the enabled sites, or revoke the site's access in Chrome.
  • Delete all data, including the activity log: uninstall the extension (chrome://extensions → Remove); Chrome deletes the extension's storage with it.
  • Keep a copy: Backup → Export workspace.

Children

Mockadabra is a software-development tool and is not directed at children.

Security

Data stays on your device and is protected only by your operating-system account and browser profile. Secrets are not encrypted at rest. Please report security issues privately to lacosta.code@gmail.com.

Changes to this policy

If a future version changes what the extension processes or transmits, this policy will be updated and the change described in the extension's release notes before that version is published.
